# Historical Archive

## Purpose

This directory preserves historical legacy spec files, old compatibility references, old task ledgers, and archived rationale.

Nothing here is the current source of truth. Current behavior lives in `../README.md`, `../spec.md`, `../architecture.md`, `../contracts.md`, `../ui-review-workflow.md`, `../eval-and-optimizer.md`, `../decisions.md`, `../plan.md`, `../tasks.md`, and JSON schemas under `../contracts/schemas/`.

## Structure

- `compatibility-refs-*/`: older focused markdown that used to live under active spec subdirectories
- `research-and-ideas-*/`: archived rationale or superseded supporting material
- `task-ledgers/`: old task/status ledgers
- `verbatim/`: preserved legacy major spec files from the pre-unification stacks

## How to use it

- Read the active spec set first.
- Use archive files only when you need old wording, historical acceptance language, deeper superseded rationale, or old status context.
- Do not cite archive files as current behavior.

## Editing rule

Do not turn this directory into a second current spec surface.

If historical material needs to stay, keep it as preserved history rather than adding new migration bookkeeping layers.
